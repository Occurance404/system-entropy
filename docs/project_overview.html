Entropic Stress-Test Framework

A reliability engine for autonomous coding agents

Research Project — V3 Architecture

The Problem

LLM-based coding agents fail silently on long-running tasks. They report high confidence while producing broken output. Current approaches:

🔥
Context Rot

Agents degrade over time — not from lack of knowledge, but from confusion as context accumulates and requirements shift.

🎭
Silent Failures

Agent says "I fixed it" but nothing changed. Or it loops, repeating the same action. Token-level entropy doesn't catch this.

💣
Blunt Recovery

Current fix: "wipe context after 3 failures." This throws away useful diagnostic info and restarts from scratch.

What I Built

A framework that stress-tests agents with changing requirements (shocks) and measures Semantic Collapse — when the agent's reasoning fragments even if it sounds confident.

Key Metric: Semantic Collapse Ratio (SCR)

Mean pairwise cosine distance between N parallel agent responses. High SCR = agent is "fractured" — different branches give wildly different answers. Low SCR = consistent (could be consistently wrong, but at least coherent).

V3 Architecture — The Plan

Moving beyond measurement to active intervention. Six new components address gaps in current reliability approaches:

🔍
Action Classifier NEW

Detects what agent actually did: EDITED, REASONED, FAILED, or LOOPED. Catches "talked but didn't act" failures.

📊
Token Budget Manager NEW

Priority-based context allocation. Errors never dropped. Lower priority items (embeddings) dropped entirely before truncating critical info.

🔄
Graduated Recovery NEW

5-level escalation: prune → summarize → wipe → swap driver → rollback. Try cheap fixes before nuking everything.

🚦
Failure Taxonomy Router NEW

Different failures get different responses. Syntax error → rollback. Test fail → add to context. Loop → wipe.

🔗
Multi-File Coherence NEW

Tracks cross-file dependencies. Detects when editing utils.py breaks main.py before tests run.

⚡
Semantic Drift Detector NEW

Pattern-matches diffs for logic inversions: > ↔ <, and ↔ or. Catches bugs that pass syntax checks.

V3 Components — Deep Dive

1. Action Classifier

What it does: Watches what the agent actually did, not what it said it did.

The problem it solves: Agent says "I've updated the file" but it didn't call any tool (just talked), the tool errored, or it's repeating the same response in a loop.

How it works: Looks at agent response, tool calls made, and actual workspace diff. Outputs one of: EDITED, REASONED, FAILED, LOOPED. For loop detection: compares current response to last 3 responses — if >85% similar, it's looping.

Why you need it: Without this, you can't tell if the agent is stuck. It might look busy but accomplishing nothing.

2. Token Budget Manager

What it does: Controls exactly what goes into the agent's context window and in what order.

The problem it solves: Context gets too long, something gets cut. Sometimes it's the error message (bad), sometimes it's old search results (fine). No control over what gets cut.

How it works: You set a total budget (e.g., 8K tokens). Each context type has a priority and max allocation. When over budget: drops lowest priority stuff entirely (doesn't half-truncate). Never drops errors — they're priority 1.

Why you need it: Predictable context = predictable agent behavior. No more "it forgot the error message" bugs.

3. Graduated Recovery Controller

What it does: When things go wrong, tries small fixes first before nuking everything.

The problem it solves: V2 approach: "3 failures? Wipe entire context and start fresh." This throws away useful diagnostic info the agent learned.

Level Trigger Action
1 First failure Prune old tool outputs (>5 steps old)
2 Second failure Summarize old reasoning into a short digest
3 Third failure Full context wipe
4 Fourth failure Swap to a stronger model
5 Fifth failure Git rollback to last working state

Why you need it: Cheaper interventions often work. No need to nuke from orbit every time.

4. Failure Taxonomy Router

What it does: Different failures get different responses.

The problem it solves: V2 treats all failures the same: "it failed, retry." But a syntax error is different from a test failure is different from the agent looping.

Failure Response
Syntax error Rollback that edit, try again
Test failure Add error to context, let agent see it
Coherence failure Inject cross-file references it's missing
Same error 3× Escalate recovery level
Agent looping Wipe context completely
Score dropped Git rollback

Why you need it: Right response to right problem. Don't wipe context just because of a typo.

5. Multi-File Coherence Index

What it does: Tracks which files depend on which other files.

The problem it solves: Agent edits utils.py, changes a function signature. But main.py still calls with the old signature. Tests might catch this... eventually.

How it works: Parses each file's function signatures and imports. Builds a map of dependencies. When a function changes, checks if callers are now broken. Flags issues before tests even run.

Why you need it: Catches cross-file breaks immediately, not after a confusing test failure.

6. Semantic Drift Detector

What it does: Catches logic bugs that pass syntax checks.

The problem it solves: Agent changes if price > 100 to if price < 100. Syntax is valid, tests might pass if edge case not covered, but logic is completely inverted.

How it works: Scans the diff for "semantic flip" patterns like > ↔ <, and ↔ or, == ↔ !=. Flags as "warning: possible logic inversion." Optional LLM sanity check.

Why you need it: Some of the worst bugs are invisible to syntax checkers and test suites.

Existing Components (Already Built)

These components form the foundation that V3 builds upon:

🎛️
Orchestrator

The main loop controller. State machine that manages the agent lifecycle and coordinates all other components.

💾
Memory Store

Persistent state via STATE.json (current goal) and EVENTS.jsonl (append-only history log).

👁️
Observer

Captures diffs and stdout/stderr from each step. Feeds data to Context Engine and Validation Layer.

📸
Git Checkpoint Manager

Transaction semantics for edits. snapshot() after each step, rollback(n) to restore.

📦
Context Builder

Assembles the context pack from multiple sources. Now enhanced with Token Budget Manager.

🔗
Hard/Soft References

Hard: Stack traces, git diff, import graphs. Soft: grep/ripgrep, embeddings. Priority-ordered.

🤖
Agent Driver

The LLM wrapper. Supports swappable backends (DeepSeek, Codex, GPT-4, Claude).

🐳
Sandbox Workspace

Docker or local execution environment. Isolated, git-tracked filesystem with auto-commit per step.

✅
Lazy Validator

Auto-runs project tests (pytest, npm test, cargo test). Returns PASS/FAIL/REGRESSION.
